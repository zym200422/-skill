# 租房风险模式库 V1.1（黄金标准首批 + Step 7 转正）

- 更新日期：2026-09-13
- 当前状态：14 个 `RISK-DRAFT` 已完成清洗与归并；黄金标准首批为 `RISK-LEASE-001` 至 `RISK-LEASE-004`，Step 7 复核后新增 `RISK-LEASE-005`。
- 核心原则：风险不是由关键词直接得出，而是由“触发条件 + 排除条件 + 加重条件 + 降级条件”共同判定。

## 目标

把第二阶段的 14 个风险草案清洗为一组可检索、可执行、可溯源的租房合同风险规则。每条规则必须回答四个问题：

1. 合同里出现了什么现象？
2. 这个现象可能涉及什么法律问题？
3. 租客可能遭受什么实际后果？
4. Skill 下一步应当执行哪些审查动作？

## 四层风险模型

| 层级 | 名称 | 作用 | 示例 |
| --- | --- | --- | --- |
| Level 1 | 现象 | 识别合同或事实信号，但不直接定级 | “提前退租赔偿剩余全部租金” |
| Level 2 | 法律问题 | 把现象接入法律规则 | 违约金是否过高；押金是否被不当没收 |
| Level 3 | 实际后果 | 说明租客可能损失什么 | 押金、高额违约金、继续居住权 |
| Level 4 | 审查动作 | 规定 Skill 需要继续读取和追问的上下文 | 剩余租期、通知期、房屋是否重新出租、实际损失证据 |

## 风险等级

| 等级 | 含义 | 使用标准 |
| --- | --- | --- |
| 🔴 P0 | 高危 | 可能导致大额经济损失、无法正常居住、核心居住权严重受损或明显安全问题 |
| 🟠 P1 | 重点协商 | 比较可能导致押金损失、高额违约金或退租纠纷 |
| 🟡 P2 | 签约前确认 | 条款不完整或语义不足，需要补充约定，但尚不能判断必然不利 |
| 🔵 P3 | 普通提醒 | 属于证据、流程或注意事项，不构成对条款本身的风险认定 |

等级必须随上下文变化。同一个“押金”字段，三要素齐全时可以不报警；只有“押金”二字且扣除方式完全交给出租人单方决定时，才升到 P0/P1。

## 通用判定顺序

```text
提取条款
  ↓
判断是否命中触发条件
  ↓
检查排除/降级条件
  ↓
叠加加重条件
  ↓
读取关联法律和案例
  ↓
估算潜在暴露
  ↓
输出等级、原因、审查问题、修改建议
```

Skill 不得在只看到“押金”“违约金”“维修”“转租”等词时直接输出风险。必须至少完成一次上下文核对。

## 用户损失模型

风险库使用“潜在暴露”而不是“法院一定会判赔”的表述。潜在暴露用于签约前谈判排序，不是法律结论。

常用计算：

```text
按剩余租金比例计算的违约金暴露
= 月租金 × 剩余租期月数 × 合同约定比例

理论最大暴露
= 违约金暴露 + 可能被扣押的押金
+ 合同明确约定且可重复计算的其他费用
```

约束：

1. 没有合同依据、没有凭据或明显过高的项目，应标注“可能被酌减或不支持”，不得直接累加进结论。
2. 房东后续重新出租、止损期、租客过错、房东违约、法定解除事由都会改变结果，输出时必须保留条件。
3. 只要有足够参数，就给出金额估算；缺少参数时输出计算公式和需要用户补充的字段。

示例：月租 1800 元，合同约定提前退租支付剩余租期 50% 的租金，剩余 8 个月，押金 1800 元。

```text
违约金暴露 = 1800 × 8 × 50% = 7200 元
理论最大暴露 = 7200 + 1800 = 9000 元
```

## 风险卡片格式

每个正式风险至少包含：

1. 风险 ID、名称、模式簇、状态。
2. 四层风险模型。
3. 触发条件、排除条件、加重条件、降级条件。
4. 风险等级判定。
5. 法律依据，只能引用既有 `LAW-*` ID。
6. 案例依据，只能引用既有 `CASE-LEASE-*` 或明确标注为线索的材料。
7. 审查问题清单。
8. 用户后果与潜在损失估算。
9. 建议措施。
10. Skill 输出示例。
11. 边界与不得过度提示之处。
